# FPA-P07-S04 — Restricted Event guest access

## Outcome

ADR-0009's authenticated Guest boundary is implemented. A Guest membership is
inert by itself: access requires a currently valid `EventAdmission` and either
the Event Album's shared `guest_participation` or an individual Event-scoped
grant. Guests navigate from the admitted Event into its Albums and Photos and
never receive an ordinary Family Space browsing path.

## Implementation

- Added Event-scoped invitation acceptance, direct admission, revocation and
  re-admission. Existing active membership roles are retained unchanged.
- Added the live, configurable admission lifetime with a 30-day default and no
  expiry sweep.
- Added `guest_participation`, Guest-aware Album/Photo/media policies and
  queries, scoped upload finalisation, and the narrow preserved-original
  download exception.
- Kept Event-scoped individual grants additive while preserving the non-Event
  Guest denial and withholding original download at participation `none`.
- Split comment/reaction authority from archival Story authoring so admitted
  Guests may participate conversationally but cannot create Stories.
- Excluded Guest memberships from ordinary Family Space and membership
  presentation, while retaining them for provenance and audit continuity.
- Added reversible Event removal/restoration and tenant teardown of Phase-7
  rows.
- Added typed feature API functions, TanStack Query hooks, an Event access
  management surface, scoped Album detail/upload navigation and invitation
  return routing.
