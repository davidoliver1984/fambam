# FPA-P10-S05 — Face identity correction workflows

## Session objective

Implement ADR-0012's suppression, cluster correction and Person-merge
integration without beginning recognition consent, calibration or polished UI.

## Work completed

- Added forced-RLS, tenant-consistent `face_identity_suppressions` with one
  durable row per FaceObservation/Person pair and audited reopening.
- Made active suppressions block automatic candidate generation and later
  manual proposals until an Owner or Administrator explicitly reopens them.
- Added current-generation cluster merge, split, naming proposal and naming
  confirmation. Human corrections retire source clusters and preserve their
  memberships as inactive history; naming resolves through ordinary identity
  assignments rather than putting Person identity on clusters.
- Extended Person merge snapshots, reconciliation and guarded reversal across
  face identity assignments and suppressions. Pending assignments are captured,
  withdrawn and then repointed for integrity; reversal restores their original
  Person and pending state from the snapshot.
- Reconciled ADR-0012 and the implementation guide to state that ordered merge
  rule without changing the accepted architecture.

## How the system works

Rejection creates or reuses a suppression row, so automatic scoring cannot
silently resurface the same face/Person pair. Cluster edits act only on active
clusters belonging to the Family Space's active generation. Merge and split
create replacement cluster history; confirmation turns every cluster member
into an ordinary reviewed FaceIdentityAssignment and then retires the cluster.

## Decisions

- A withdrawn assignment's repointed Person foreign key is inert relational
  bookkeeping, not a live suggestion about the merge survivor.
- Suppression history remains a durable row plus audit history; reopening does
  not delete and recreate the suppression.
- No numeric recognition or clustering threshold was accepted in this stage.
