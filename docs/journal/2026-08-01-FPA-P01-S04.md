## How the system works

Applications send OTLP/HTTP telemetry only to the Collector. The Collector
batches telemetry, writes detailed local diagnostic output and forwards traces
and metrics over OTLP to Grafana LGTM. This keeps the application-facing
telemetry boundary independent of its local backend.

Laravel creates a server span for API requests and attaches request and
correlation identifiers to JSON logs and responses. The synthetic verification
endpoint creates a producer span and carries its W3C trace context on SQS. The
stateless Python verifier extracts that context, creates a consumer span and
emits a structured log with the message, correlation and trace identifiers.

## Corrections made during verification

- PHP automatic root-span startup ran before the OTLP exporter registered, so it
  was replaced with explicit Laravel request middleware instrumentation.
- The first smoke test checked for two span names but did not compare trace IDs.
  Detailed Collector inspection caught the disconnected consumer trace; the
  verifier now compares the exact producer and consumer trace IDs.
- Old synthetic queue messages could make repeated runs consume the wrong test
  message. Correlation IDs now select the current verification message.

## Security, privacy and operations

Telemetry contains operational identifiers and route/message names only. The
synthetic payload contains no photograph, person, account or family data. Logs
must not include image bytes, credentials or sensitive family metadata.
