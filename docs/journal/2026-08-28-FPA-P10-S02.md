# FPA-P10-S02 — Embedding storage and similarity queries

## Session objective

Implement ADR-0012's authoritative-embedding projection boundary and
provider-neutral similarity-search contract without beginning face clustering,
identity suggestion or threshold calibration.

## Work completed

- Replaced the local and disposable PostgreSQL images with a PostgreSQL 17
  image carrying pgvector and made extension creation part of migration order.
- Added the supporting `(id, family_space_id)` uniqueness constraints to
  `face_observations` and `people` before their future composite relationships.
- Added tenant-owned `face_embedding_projections` with forced RLS, composite
  FaceObservation tenancy, one projection per observation, dimension checks,
  projection version and authoritative-source SHA-256.
- Kept `face_observations.embedding` byte-for-byte authoritative and immutable.
  Float32 little-endian decoding and vector rendering are deterministic and
  reject malformed dimensions or non-finite values.
- Added a tenant-bounded rebuild command. Projection drift is excluded from
  search by source-checksum verification and repaired by deterministic rebuild;
  rebuilding never mutates the parent observation.
- Integrated projection creation into successful Phase 9 persistence in the
  same database transaction, while leaving SQLite-only business tests free of
  pgvector dependencies.
- Added a Fambam-owned `SimilaritySearch` contract and value objects. The
  PostgreSQL implementation alone owns pgvector SQL and scopes by Family Space,
  projection version, embedding dimension and the complete provider/model/
  weight-checksum/config-hash identity.
