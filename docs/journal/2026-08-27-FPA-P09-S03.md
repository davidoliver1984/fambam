# FPA-P09-S03 — Face-analysis provider contract

## Session objective

Implement ADR-0011's language-neutral provider and transport contracts,
tenant-consistent persistence schema, result-artifact validation and signing-
audience extension without beginning real inference or the queued pipeline.

## Work completed

- Added versioned JSON Schema documents for `ImageAnalysisRequested`,
  `ImageAnalysisCompleted`, `ImageAnalysisFailed`, the shared domain types and

- Added a deterministic repository contract validator and made
  `make contracts-check` exercise the real schemas.
- Added strict Pydantic request/result models and a directly callable,
  provider-neutral Python protocol with no HTTP or database dependency.
- Added the Laravel run/attempt/observation models, statuses, failure categories

- Enforced the logical run identity and all three tenant-consistent composite

- Added explicit browser/service signing audiences while preserving existing
  browser endpoints and write-once authority.

## How the system works

The language-neutral schemas are the source contract shared by Laravel and
Python. Python exposes only a replaceable protocol which accepts a verified
canonical file and returns provider-neutral detected faces. Laravel remains the
sole future producer, validator and database writer.

A logical `FaceAnalysisRun` owns one or more independently identifiable
dispatch attempts. The successful result becomes immutable observations on the
run. Composite foreign keys carry `family_space_id` through every relationship,
so RLS is backed by database-level tenant consistency rather than merely hiding
an inconsistent row.

Browser-signed URLs continue to use the host-reachable endpoint. Future worker
messages request the service audience, which embeds the Docker-network or
production service endpoint in the signature without granting standing S3
permissions.

## What I learned

### Laravel and software engineering

An at-least-once transport needs a durable attempt identity distinct from the
long-lived logical result identity. Composite foreign keys require matching
unique parent keys even when the parent's globally unique identifier remains
its sole domain identity.

### Python and image analysis

A provider interface can be useful before a model exists when its domain output
is strict, immutable and directly callable. Keeping provider diagnostics opaque
prevents a future model's native response schema from leaking into application
logic.

### Security, privacy and operations

Checksums and write-once storage do not make an external artifact trusted.
Cardinality, size, numeric and geometry bounds still need independent Laravel
validation. Signed URLs must also be generated for the network audience that
will actually use them.

## Decisions

No new architectural decision was made. Conservative placeholder limits are
implementation defaults explicitly intended for S04 calibration under
ADR-0011. The existing browser/service signer is one abstraction with an
explicit audience, not two unrelated implementations.
