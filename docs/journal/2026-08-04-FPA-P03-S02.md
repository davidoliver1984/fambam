# Session 2026-08-04 — FPA-P03-S02

## Session objective

Implement ADR-0005's family-space and membership domain foundations without
pulling forward slug-based tenant resolution, policies, PostgreSQL RLS or the
deletion lifecycle from later Phase 3 stages.

## Active scope

- Create the Family Space and membership schema and models.
- Make bootstrap create the first user, Family Space and Owner membership
  atomically without granting ongoing Family Space creation authority.
- Add audited operator grant/revoke commands for the narrow
  `can_create_family_spaces` capability.
- Implement atomic Family Space creation with its initial Owner membership.
- Implement membership roles, removal/reactivation and the independent
  application/database last-Owner safeguards.
- Make invitations family-scoped and support both new-account membership and
  existing-account rejoin semantics.

## Explicitly deferred

- Friendly-slug route resolution, TenantContext middleware, policies and
  explicit tenant-scoped query objects belong to FPA-P03-S03.
- PostgreSQL RLS roles and policies belong to FPA-P03-S04.
- The complete deletion state machine and audit-history surface belong to
  FPA-P03-S05.

## Work completed

- Added ULID-backed `family_spaces` and `family_space_memberships`, the five
  accepted roles, soft membership removal metadata and Family Space lifecycle
  status fields.
- Added the application last-Owner check and a deferred PostgreSQL constraint
  trigger that independently rejects a commit leaving a non-deleted Family
  Space without an active Owner.
- Changed bootstrap to create the first account, Family Space and Owner
  membership atomically, without granting ongoing creation authority.
- Added idempotent, operator-attributed grant/revoke commands for
  `can_create_family_spaces`, and retired the Phase 2 `can_invite` column.
- Added capability-gated Family Space creation, active-membership listing and
  the corresponding typed TanStack Query frontend flow.
- Made invitations Family Space- and role-specific, authorized issuance and
  management through active Owner/Administrator membership, and added
  existing-account joining plus atomic in-place reactivation of removed
  memberships.
- Added application, API, frontend and PostgreSQL-specific regression coverage.
