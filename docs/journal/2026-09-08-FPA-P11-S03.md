# FPA-P11-S03 — Relationship-aware search and Discovery

## Session objective

Add the accepted People and Event search axes, relationship-aware filters,
authorization-scoped autocomplete and every functional Discovery traversal
without widening any actor's existing content access.

## Work completed

- Added Gate-protected People search over preferred and alternate names.
- Added an actor-aware Event query that exposes tenant Events to ordinary
  members and only currently admitted Events to Guests.
- Added approved multi-Person intersection and combined Person, Event and
  historical-date filtering for Photos and their Stories.
- Added bounded People, Album, Event and visible-Photo-derived tag suggestions.
- Added Person, Photo, Album and Event Discovery endpoints whose every
  relationship hop begins from an independently authorized query boundary.
- Added typed feature API functions, TanStack Query hooks, role-aware Person and
  Event pickers, typed result groups and related-memory navigation.

## Decisions

- Contributor and Guest requests never invoke People-directory search or
  autocomplete; explicit People-group requests remain forbidden.
- Discovery stays a bounded traversal of recorded family facts. It introduces
  no recommendation, inference or semantic-search state.
- Search filters select People and Events by human-readable suggestions rather
  than exposing raw ULIDs as the product workflow.

## Verification

- Foundation, documentation, formatting, lint, type checking, contracts and
  `git diff --check` passed.
- The complete web, Laravel and image-analysis suites passed.
- Disposable PostgreSQL integration passed with 35 tests and 364 assertions.
- Focused relationship-search tests covered directory denial, Guest Event
  admission, approved-Person intersection, visible tag autocomplete and all
  four Discovery anchor types.
- The rebuilt local web and API services passed their health checks and the
  Search preview was visibly verified.
