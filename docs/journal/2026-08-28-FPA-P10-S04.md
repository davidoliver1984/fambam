# FPA-P10-S04 — Identity suggestion and confirmation

## Session objective

Implement ADR-0012's face-level identity claims, trusted galleries,
confidence-banded candidate generation and deterministic PhotoPerson
confirmation without beginning suppression, cluster editing, consent or UI.

## Work completed

- Added forced-RLS, tenant-consistent `face_identity_assignments` with
  `pending`, `approved`, `rejected` and `withdrawn` states and a partial unique
  index enforcing one active claim per FaceObservation.
- Preserved rejected and withdrawn rows as history while allowing a later
  pending or approved claim.
- Extended the Fambam-owned similarity interface with approved trusted-gallery
  references; Family Space and full embedding-space identity remain mandatory
  and pgvector details remain inside the PostgreSQL adapter.
- Added gated strong, shortlist and no-suggestion outcomes. Fixture-only
  settings verify that one reference remains cautious and closely competing
  people produce an ephemeral shortlist rather than a persisted guess.
- Added privacy-bounded suggestion-count, candidate-count and scoring-duration
  telemetry without Person identifiers, embeddings or named scores.
- Implemented Member proposal and Owner/Administrator approval against visible,
  promoted Photos.
- Implemented the four deterministic approval transitions: create a new
  approved PhotoPerson, reuse an existing approved row, resolve a pending row,
  or preserve rejected history and create a later approved row. Assignment and
  PhotoPerson decisions are audited atomically.
