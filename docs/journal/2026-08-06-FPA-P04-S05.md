# FPA-P04-S05 — Person merge and correction workflow

**Date:** 2026-08-06

**Status:** Completed — implementation and full Phase 4 gate passed

**ADR:** ADR-0006 §12

## Scope

This stage implements Person duplicate proposals, Owner/Administrator merge,
redirect/tombstone identity continuity, atomic reconciliation of every
Phase-4-owned reference, structured merge provenance and reversal only while
the recorded state remains unambiguous.

## Implementation

- Added Family-Space-owned merge and proposal records with forced Class C RLS,
  partial uniqueness for active tombstones and a structured before/after
  provenance ledger separate from AuditEvents.
- Kept absorbed People as soft-deleted tombstones. Their immutable ULIDs resolve
  to the survivor while active Person lists omit them.
- Reconciled canonical relationships, relationship proposals, Circle
  memberships and User links in one locked transaction. Exact duplicates
  collapse, self-edges disappear, conflicting edges fail safely, and dual
  account links require an explicit resolution.
- Added Member duplicate proposals and Owner/Administrator approval, rejection,
  direct merge and reversal policies with distinct audit events.
- Restored the exact pre-merge Phase 4 state only when the current state matches
  the ledger's post-merge snapshot and account-link uniqueness remains safe.
  Ambiguous attempts persist `manual_correction_required` and leave state
  unchanged for deliberate manual repair.
- Added typed feature API functions, tenant-aware TanStack Query hooks and an
  accessible role-dependent merge panel without direct page/component HTTP or
  raw server-state `useEffect` calls.
