## How the system works

`make up` builds the three applications and starts the complete platform.
Infrastructure health checks must pass before Laravel starts; Laravel applies
migrations and must become healthy before the web container starts. LocalStack
creates the required bucket and queues through a ready hook. `make down` removes
containers and the network but retains the named data volumes.

The infrastructure smoke script tests dependencies directly, then exercises
Redis caching, S3 object operations and SQS publishing through Laravel's actual
configuration. This catches both infrastructure failures and application
integration mistakes.

## What I learned

### Local platform isolation

Common development ports were already occupied by unrelated local projects.
fambam uses a dedicated default host-port range while keeping standard internal
container ports. The root environment template makes every host binding
overridable without changing committed Compose configuration.

### Security, privacy and operations

Application containers run as non-root users. Local credentials are explicitly
non-production defaults, and health responses expose no family data or secrets.
Redis is used only for cache and ephemeral state; SQS remains the message
transport required by ADR-0003.

## Decisions

- Used health-gated Compose dependencies so readiness is deterministic.
- Used named volumes for PostgreSQL, Redis and LocalStack persistence.
- Kept object-storage and queue bootstrap idempotent.
- Kept OpenTelemetry and observability UI work out of this stage.
- Left the platform running after verification for immediate local review.
