# FPA-P10-S06 — Recognition consent and exclusion

## Session objective

Implement ADR-0012's explicit recognition opt-in and exclusion behavior
without changing manual tagging, calibrating thresholds or enabling automatic
processing.

## Work completed

- Added `people.recognition_allowed` as `NOT NULL DEFAULT false`, producing an
  automatic database backfill for every existing Person.
- Added a dedicated Owner/Administrator consent endpoint and exposed current
  consent and management permission in Person responses.
- On the true-to-false transition, withdrew every pending identity assignment
  naming the Person as one transaction and one audited action.
- Excluded opted-out People at both the PostgreSQL trusted-gallery query and
  the provider-neutral candidate-generation boundary.
- Preserved approved assignments, `PhotoPerson` facts, observations,
  suppressions and manual assignment behavior; re-enabling consent does not
  resurrect withdrawn suggestions.

## How the system works

Recognition starts disabled for every Person. Owners and Administrators may
opt a Person in through the dedicated endpoint. Opt-out immediately removes
the Person from live matching and retires currently pending machine opinions;
confirmed human facts remain historical truth and are not modified.

## Decisions

- Consent is not part of general biographical editing and has its own audited
  endpoint and transaction.
- A no-op request produces no audit event because no consent change occurred.
- S06 changes eligibility only; all recognition and clustering numbers remain
  unset until S07 calibration.
