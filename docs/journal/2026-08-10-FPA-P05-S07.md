# FPA-P05-S07 — Upload recovery and bulk upload

## Outcome

Completed Phase 5 with source-bound degraded-processing recovery, independent
per-file bulk upload reporting, retryable abandoned-upload cleanup and
idempotent Family Space media teardown. Phase 6 was not started.

## Decisions implemented

- Recovery reuses the frozen original or canonical checksum and claims the
  state transition before redispatch; it never rewrites the preserved original.
  Owner and Administrator can recover work orphaned when its uploader can no
  longer act.
- A bulk selection shares only an `upload_batch_id`. Each file retains its own
  idempotency key and succeeds or fails independently.
- Initiated uploads expire after 24 hours by default. Cleanup marks the row
  abandoned before deleting staging bytes and records successful deletion
  separately so storage failures remain retryable.
- Family Space deletion removes only its three Phase 5 media prefixes and
  Phase-5-owned rows. It remains the sole preserved-original deletion exception.

## Verification

Focused backend and frontend suites, static analysis, persistent migration and
PostgreSQL 17.6 RLS/discovery coverage passed. The complete repository and real
LocalStack acceptance gates are recorded in the stage review handoff.
