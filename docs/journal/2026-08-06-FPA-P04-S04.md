# FPA-P04-S04 — Relationships and Family Circles

**Date:** 2026-08-06

**Status:** Completed — implementation and full stage gate passed

**ADR:** ADR-0006 §§7–9, §§11, §§14–16

## Scope

This stage implements canonical Person relationships, the bounded
proposed-versus-authoritative relationship flow, current-state structural
validation and flat People-only Family Circles. Person merge remains assigned
to FPA-P04-S05.

## Implementation

- Added one canonical edge per relationship concept, with deterministic
  normalization for symmetric types and perspective-dependent inverse wording
  for directed types.
- Centralized the fixed additive V1 vocabulary and rejected self-relationships,
  duplicates, direct inverse parent cycles and defined incompatible same-pair
  combinations.
- Added separate pending relationship proposals. Member may propose create,
  replacement, dispute or removal; Owner and Administrator may act directly or
  approve/reject proposals. Approval revalidates current state.
- Added deterministic Person locking so concurrent edge writers serialize
  before validation.
- Added flat Family Circles and People-only Circle membership. Owner,
  Administrator and Member may manage Circles; Circle data is not consulted by
  any authorization or tenant-boundary decision.
- Added scoped queries, policies, audit events, deletion-lifecycle integration
  and forced Class C RLS for relationships, proposals, Circles and memberships.
- Added typed feature APIs, tenant-aware TanStack Query hooks and role-dependent
  relationship and Circle controls, following the frontend engineering
  standard without an unrelated frontend migration.
