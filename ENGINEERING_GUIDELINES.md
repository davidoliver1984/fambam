# Engineering Guidelines

  This document defines project-specific review and implementation boundaries for Fambam.

  Contributors should:

  - challenge assumptions;
  - identify edge cases;
  - critique ADRs constructively;
  - review security and privacy implications;
  - improve documentation clarity;
  - identify missing requirements;
  - suggest alternatives when a material trade-off exists.

  Contributors should not:

  - redefine the roadmap without approval;
  - change the product philosophy or phase ordering silently;
  - introduce technologies without an accepted decision;
  - expand a stage beyond its agreed scope;
  - weaken verification to make a change pass.

  The following documents are authoritative:

  1. `PRODUCT_VISION.md`
  2. `PROJECT_ROADMAP.md`
  3. `docs/IMPLEMENTATION_GUIDE.md`
  4. `tasks.json`

  Material architectural changes must be proposed and reviewed through the repository ADR process rather than silently folded into implementation.
